# C6 plan: qualified picks through the app pipeline, the wager contract and Gemini

Owner request 2026-11-06: "Will my picks go through our pipeline and include Gemini analysis?"

## Where things stand

* The research picks and the Pinnacle value boards are produced by research workflows,
  outside the app pipeline (`core/streamlit_pipeline.run_analysis_pipeline`). They never reach
  the wager contract or Gemini, by design while they are unproven ($0).
* The app pipeline's own ML model targets the home win and is blocked for spreads and totals
  ("Unsupported Target"). A qualified NCAAB spread market would have **no rows in the
  pipeline that carry the qualified model**, so nothing would be staked and Gemini would have
  nothing to review.
* The authority chain on the pipeline side is already complete:
  `core/live_wager_contract` → `core/sport_market_gate.market_gate` (exact deployment from
  `prospective_evidence.deployment_state`, owner activation, exposure ledger) →
  maturity → **Gemini secondary review** (rows that pass the deterministic checks) → stake.

## What `market_gate` requires of a row (all must hold, or it records a blocker)

| Requirement | Row fields |
|---|---|
| Exact deployment | `sport`, `market_type` mapping to the deployed family |
| Same model and calibration as the reviewed deployment | `model_id`, `model_version`, `calibration_id`, `calibration_version` |
| Chronology | `model_trained_through < prediction_generated_at <= now < start`; `model_available_at`, `calibration_available_at`, `evidence_frozen_at`, `quote_time` all `<= prediction_generated_at` |
| Provider identity | `provider_namespace`, `provider_event_id`, `identity_verified=True`, `team_ids` (two stable IDs) |
| Exact fresh quote | `selection`, `line`, `odds_american`, `book`, `exact_quote_verified=True`, quote at most 30 minutes old |
| NBA/NCAAB/NHL books | canonical binding: `prospective_quote_id`, `prospective_event_id`, `quote_source_id`, `quote_source_hash`, `game_id` replaying against the stored raw response |
| Owner authority | a current market activation and exposure ledger (`sport_market_activation`) |

## The build: a bound-prediction bridge

1. **Fresh bound predictions at decision time.** For a qualified market, the research cycle
   (`prospective_calibration`) already records bound predictions (`prospective_prediction`)
   against canonical quotes. Add a near-kickoff step that records a prediction from the
   deployed model and calibration against a quote captured within the last 30 minutes, so
   the row passes the freshness check. It reuses the capture adapter and the slate loop's
   timing (closing-capture-slate), with the same credit budget.
2. **Bridge into the pipeline.** A new `app_core/qualified_bridge.py` reads, for each
   *qualified* market only (`app_core.selection.qualification`), the latest bound prediction
   per upcoming game from the restored canonical store. It converts each into a best-pick row
   carrying every field above, taken from the stored prediction, quote, event and model
   records (never recomputed or guessed). In `run_analysis_pipeline`, these rows replace the
   app's own pick for that sport and market. Other markets are untouched.
3. **Through the existing chain, unchanged.** The rows then go through the live wager
   contract, the market gate, maturity and the **Gemini secondary review**, then stake sizing
   under the owner's activation and exposure limits. No new authority path is added.
4. **Pinnacle-value picks**, if a price-based policy qualifies instead of a model: the same
   bridge, with the plan bound to that policy. The policy would first need its own frozen plan
   (a model-free plan family), so this is a later step that depends on what the data shows.
5. **Tests**: the bridge produces rows that pass `market_gate` with a synthetic validated
   deployment and activation; unqualified markets produce no rows; stale quotes, model
   mismatches and chronology violations produce the exact blockers. Then an end-to-end test:
   bridge row → contract → Gemini stub → stake.

## Before it is needed

* **Gemini key**: confirm `GEMINI_API_KEY` (or `GOOGLE_API_KEY`) is set in the Streamlit secrets.
  The wager contract's outage policy caps stake when the review is unavailable.
* **Timing**: NCAAB spread's validation window is expected to finish around mid-December, so
  this should be built and merged by early December. It can be built and fully tested now
  against synthetic deployments.
* **Runtime binding**: `core/streamlit_pipeline.py` and `core/live_wager_contract.py` are not in
  the NCAAF runtime binding (checked 2026-11-06), so no rebind is needed unless
  `streamlit_app.py` itself has to change.

## Built (2026-11-06)

* **Step 2 and 3**: `app_core/qualified_bridge.py` and its hookup in `run_analysis_pipeline`
  (`PARLAYPICKER_QUALIFIED_BRIDGE=true`).
* **Step 1**: `app_core/decision_capture.py`, `scripts/decision_capture_loop.py`, workflow
  `decision-capture.yml` (evenings, and weekend afternoons, for up to 340 minutes, every 15 minutes).
  * Off unless the repository variable `PARLAYPICKER_DECISION_MARKETS` names a market
    (for example `NCAAB:SPREAD`); a named market is used only while it is qualified.
  * One Odds API request per market per cycle, US books and that market only (1 credit), for
    stored games starting within 60 minutes. Its own allowance: `DECISION_LIMITS` 60 a day,
    1,500 per 31 days, in its own ledger on the evidence remote (it never rewrites the
    research scheduler's state). An unexpected provider charge stops it until reviewed.
  * A quote from a later capture of a stored game now carries its own provider response
    (`prospective_evidence.quote_source`), which must match the stored game exactly; before
    this, only a game's first-capture quotes could be stored as verified.
  * Bound predictions from the plan's exact model and calibration, on both sides of each
    game, against the newest quote at most 30 minutes old. The bridge offers the side with
    the better expected value.
  * Validation is unchanged: a plan scores each game's first prediction, and a decision
    prediction is made only for a game that already has one from the same model and calibration.
* **App reads the refreshed store** (2026-11-06): the market gate and the bridge already read
  the same local store (`prospective_evidence._path`: `prospective-evidence.sqlite3` beside the
  app's evidence database, when no policy names another). On Refresh, with the bridge on,
  `qualified_bridge.refresh_if_enabled` restores every remote row that store lacks: read-only
  (`app_core.read_only_drive.ReadOnlyDrive` refuses every write), cached object bytes reused
  only when they match Drive's checksum, at most every 10 minutes, one session at a time (a
  lock file), and never breaking Refresh. Off with `PARLAYPICKER_QUALIFIED_BRIDGE_REFRESH=false`.
  The app needs the Drive credentials (`PARLAYPICKER_DRIVE_FOLDER_ID`,
  `PARLAYPICKER_GOOGLE_SERVICE_ACCOUNT`) in its Streamlit secrets; without them it reports
  `MISSING_CREDENTIALS` and uses what is local.
* **Still needed before a stake**: the owner's market activation (after C4).
