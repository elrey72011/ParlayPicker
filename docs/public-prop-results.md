# Public MLB player-prop results

After merging, open **Workspace > Preview & Publish > Public results history** and restore public history from Drive. Select the game date, then **Grade MLB props for selected date**. Build a fresh preview and publish it to Netlify. On the public Results tab, select **Player Props** and filter by period, league, market and selection group.

The package already archives included player props. The tracker now uses the first eligible confirmed publication per player, statistic and matchup/day, preserving its original line, price, pick and approval label. Publication must be before game start and within 15 minutes of the original analysis. Later line/direction changes and repeat publications do not inflate the record. Include props when building the original pregame publication; a postgame publication cannot create a verified prediction.

Older original combined prop CSV exports may be imported explicitly. They require original analysis and timezone-aware start timestamps, player, matchup, supported market, pick and price. Imports are always **Imported research**, even when the CSV labels a selection approved. Supplied results/actuals are ignored. Unsupported rows are excluded and the import reports the supported count. Missing timestamps are never fabricated. Restoring old packages can recover already archived eligible props.

Supported MLB markets: batter hits and total bases; pitcher strikeouts, walks and outs. The implementation reuses the existing `grade_side`, market-to-stat mapping and innings-to-outs conversion. It fetches game-specific final boxscores instead of a player's daily aggregate to avoid doubleheader contamination. Exact normalized player names, exact matchup labels and a unique game within 30 minutes of the saved start are required. Missing stats, unfinished games, ambiguous names/games and nonparticipants remain pending; no zero or sportsbook void is inferred. These are statistical selection results, not sportsbook settlement or verified betting returns.

Each manual click uses one MLB schedule request and at most ten final boxscore requests (shared among props in the same game), each with a 10-second timeout. It uses no API key and makes no CFBD or Odds API calls. Navigation/restore/render never requests player stats. Pending-only grading is the default; check **Recheck already settled props for score corrections** to request a correction. For more than ten qualifying games, repeat pending-only grading. These requests are not added to the automatic scheduler.

Stat revisions are immutable and read-back verified under the existing site's `prop_stats/` Drive prefix; imports use `prop_imports/`. A failed backup does not update session results. Restore recomputes grades from original selections and saved revisions. Public package version 4 allows MLB prop result fields; versions 1–3 remain readable. The automatic grading status continues to describe game grading only. NFL props, automatic stat collection, DNP/book-specific settlement and DFS results are outside this first release.

Validation: unit tests cover publication timing, duplicate suppression, import separation, corrections, unique game/player matching, final status, missing stats, request limits and schema validation. Streamlit tests exercise restore, explicit grading and restoration of backed-up grades. Browser checks cover separate props/results filters and persistence. Live provider matching and Drive grading should be verified with the first eligible published prop after deployment.
