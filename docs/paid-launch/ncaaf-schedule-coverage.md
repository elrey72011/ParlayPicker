NCAAF inventory begins with ESPN schedule records from both FBS (group 80) and FCS (81), independently of available prices. It retains a row for each namespaced event, including games with no odds, no candidate, no selection, incomplete facts, cancellation or postponement. Dates use America/New_York, including next-UTC-day starts. Schedule inclusion grants no wager authority.

The college scoreboard accepts single dates. Its returned season calendar supplies week identifiers; whole-week reads cover selected ranges efficiently. When calendar metadata is unavailable, daily reads include the following UTC day. The separate paginated core event index checks each division. Inventory is COMPLETE only when every indexed event is represented and record validation succeeds. Missing pages, failed requests, revision conflicts or the six-request budget leave it PARTIAL. Six schedule requests replace the old bounded NCAAF identity capture; odds-provider and fallback budgets remain unchanged. Selected windows are limited to 31 Eastern calendar dates; multiweek windows may exhaust the budget and require smaller refresh windows. No partial result may advertise full coverage.

Canonical identity is `espn:college-football:<event-id>`. Cross-feed reconciliation uses an explicit ESPN ID with compatible teams/kickoff, or exact school aliases and one unambiguous scheduled kickoff. Similar names alone cannot merge events. Primary quotes take precedence only for an unambiguous matched event. Provider namespaces, original IDs and historical matchup IDs remain available; kickoff revisions/conflicts remain explicit. McNeese/McNeese State and Gardnerwebb/Gardner-Webb are explicit school aliases. Existing model, calibration, probability-first selection, EV, eligibility, authority and staking logic are preserved; the only selection-key adjustment keeps inventory-bound NCAAF events distinct.

Provider quote `recorded_at` and fetch `observed_at` retain their original meanings. An ESPN observation never supplies a missing quote update time. Coverage reports available quote evidence and timestamped pregame evidence separately; neither implies freshness or production qualification. Qualification counts project only existing strict wager contracts accepted by the production reader. Trial authority remains separate. Unqualified events report PASS.

The UI and CSV report scheduled, provider-matched, quoted, timestamped, ranked and qualified event counts independently. Candidate/ranking counts require actual candidate/selected records matched to schedule identity. Schedule-only rows survive the pipeline's empty-candidate path. Provider failures, absent quotes, incomplete chronology, unresolved identity, started games and cancelled/postponed games remain visible. Current schedule evidence does not reconstruct historical producer runtime, infer historical first-loss stages or identify absent original games without a matching inventory.

The successor policy `paid-launch-ncaaf-schedule-v1` retains the original baseline, v2/v3 policies, clock correction, paid-launch workflow and subscriber assertion byte-for-byte. It binds the verified starting main/tree, exact reviewed source replacements, additive module/test/document bytes, implementation commit/tree and successor tooling. A separate policy-only seal follows implementation; CI must have parents `[starting main, sealed candidate]` and the sealed tree. The seal is not embedded into its own implementation hash. Unauthorized existing-test edits, model/calibration changes, baseline changes, tooling, runtime shadows and incorrect candidate ancestry remain rejected. Original findings and retained exceptions are reported separately from this integration.
