## Reproduced mismatch and correction

`slate_coverage.publication_rows` previously matched named teams using existing
NFL/NCAAF aliases and case normalization, retaining producer labels.
`per_game_boards.per_game_board` then preferred `Home`/`Away` for the matchup,
another pair for matching, and could replace the final start with a candidate
start. `public_board.pick_record` carried these presentation fields to
`slate_coverage.validate_public_coverage`, which correctly requires the exact
canonical schedule descriptors. Equivalent aliases/case therefore failed, and
contradictory duplicate fields depended on precedence. Unmatched contradictory
final rows could also turn silently into apparently legitimate placeholders.

The new presentation reader verifies every supplied named-side label, league,
canonical ID and authoritative start alias against the retained decision and
the complete decision set. It reuses the existing exact alias normalizers;
it adds no fuzzy, daily-name or reversed-side matching. Equivalent aware
timezone representations compare as the same instant, including explicit
Eastern labels with DST ambiguity/nonexistence rejection. A genuine kickoff
change remains a conflict, rather than a presentation repair.

Only after unique verification does the per-game export present the schedule's
league, named matchup and start. Original input rows are unchanged; original
descriptors are retained separately in private `coverage_origin_descriptors`
and `coverage_candidate_descriptors`. Selection, book, price, quote identity,
inference clock and candidate evidence are not rewritten. Public records retain
their existing allowlist and exact coverage validation.

Conflicting publication rows retain every scheduled decision as a zero-stake
placeholder plus a private failure descriptor in DataFrame metadata. Every
per-game builder rejects that metadata before constructing a package. Thus the
placeholder cannot turn a conflicting candidate into a successful preview.
Genuine unmatched provider orphans remain outside the scheduled denominator.
Repeated matchups require their unique event/start identities.
An absent original final-row clock (including pandas missing scalars) retains
the independent schedule's no-inference placeholder. Its start is a schedule
fact, not an imputed candidate/inference clock; no original candidate metrics
are carried. A separate identity contradiction still rejects. This distinction
preserves the original base behavior and avoids a false conflict on missing facts.
Today catches only this stable conflict, shows every canonical schedule decision
with wagering PASS and a preview blocker, and leaves owner navigation reachable.
It does not expose the private field-level diagnostic outside the token gate.

No probability formula, blend, qualification, source acceptance, approval or
stake gate changes. Unsupported/unqualified wagering actions remain PASS at
zero stake. Informational coverage PASS/UNVERIFIED remains separate.

## Owner diagnostic before a successful package exists

After the existing Publishing token gate, a failed preview keeps
`COVERAGE_PUBLIC_EVENT_BINDING_CONFLICT` and offers **Private preview conflict
diagnostic → Download private preview conflict JSON**. It includes the canonical
event, inventory/run identities, observed stage/board category, first differing
field, expected descriptor and actual descriptor. It does not include raw rows,
probabilities, dependencies, arbitrary provider errors or credentials. Values
are bounded; URLs/control characters are omitted and the publishing token is
redacted before JSON encoding. No diagnostic is published or sent remotely.

The diagnostic participates in preview cache identity, so an earlier successful
placeholder preview cannot conceal a new conflicting original row. Other
validation codes remain unchanged. No analysis refresh is required to inspect
an already-loaded failure after the reviewed software is separately deployed.
