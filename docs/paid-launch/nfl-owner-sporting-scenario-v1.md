# Private NFL sporting scenario v1

This explicitly selected route estimates a user-specified sporting outcome. It is separate from observed offers and every existing NFL offer reader. The target is **selected team final points plus signed half-point handicap greater than opponent final points**, full game including overtime, conditional on a completed sporting result. Cancellation, abandonment and bookmaker settlement are outside this sporting condition. Integers, missing facts, neutral sites not supported by the pinned native home-advantage model, and started games remain unavailable.

`nfl-owner-sporting-scenario-v1` accepts one sealed packet, not a candidate or quote. `scenario.selected_team` must be one named event team; `signed_handicap` is explicitly supplied by the owner. Neither field is an observed offer. There is no default selection or line. No quote, operator, listing, price, EV, edge, original blend or UI refresh exists in this contract. Those fields cannot enter the exact input/result schemas. This version neither expands Novig support nor changes any offer gate.

A contradictory instant rejects; equivalent explicit offsets compare as instants. Supporting references and conclusions are owner reviewed, not independently accepted.

The complete CSV remains unchanged. A deterministic separately derived season/source-order view feeds the existing completed-before-current-UTC-day selector. Completed score/result identities are checked against original observation, then the unchanged native aggregates derive the eleven ordered NFL features. At least one eligible completed game per team is required by the existing model; four qualifying histories improve support but do not establish calibration. Missing history, altered arithmetic/order and unresolved mappings reject before numerical inference. No new publisher or game-completion timestamp is invented from a date.

Required clock order is original request ≤ body receipt ≤ first observation ≤ feature availability ≤ substantive owner review < actual new inference ≤ completion < kickoff. The event-verification observation must also precede feature availability. All clocks require explicit timezone offsets. Source permissions must cover inference. No quote-age limit is repurposed as a scoring timestamp: there is no quote in this route, and existing offer freshness rules remain unchanged.

`owner_review` names Robert Velarde, records his actual time, binds the exact subject excluding only the review itself, and records VERIFIED findings with substantive basis for event mapping, scenario definition, permissions, original custody/clocks, feature provenance and model binding. Processing, staging or an owner checkbox creates no review. A changed body, team, handicap, clock, feature or reader/runtime requires a new exact subject and review. An offer acceptance receipt cannot be borrowed here, or vice versa. Production acceptance catalogs remain untouched.

Its already-shrunk/clipped native output is retained as `native_model_output`, never relabelled calibrated or a market blend. Actual inference and finish clocks, model/runtime/source identities, original input and native output are sealed together.

New namespaced records use the existing `research_source_intakes` and `research_replay_exports` tables and original append-only triggers. They do not become offer candidates, coverage approvals, public board rows, accepted sources or qualification evidence. PASS and zero stake are immutable result conditions.
