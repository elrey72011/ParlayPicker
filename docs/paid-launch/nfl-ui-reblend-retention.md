# Prospective NFL UI refresh retention

The actual Streamlit post-Kalshi consensus caller recomputes blended research probability and EV after `run_analysis_pipeline`. The pipeline's retained EV is rounded; the UI's existing EV is full precision. Retaining only the pipeline output made an otherwise complete prospective NFL packet conflict with its later output. This successor records the actual second computation through the existing private inference metadata, snapshots, export/replay bundle and owner download.

`nfl-ui-reblend-v1` receipts append original and refreshed output states, exact consumed blend arguments, original event/offer and packet binding, actual refresh clock, current UI artifact bytes/hash and consumed configuration. The original `nfl-inference-inputs-v1` packet is unchanged. Original quote, feature observation, inference and kickoff clocks remain separate from the refresh clock. No prediction formula, weight, probability, EV, selection, qualification gate, authority or stake is edited.

Offline admission checks the complete transition chain, original named event/selected offer, inputs, code/configuration, clocks, numeric output correspondence and all predecessor feature/eligibility/source protections. Missing receipt facts remain INCOMPLETE; contradictions and corruption reject, including consistently rehashed unrelated-event, altered-offer, changed-output, false-input-state and wrong-code fixtures. Numeric external Kalshi/TheOver or nonneutral sentiment inputs alone do not supply upstream evidence. Changed market inputs without an original source binding also remain INCOMPLETE. This scope records such computations without claiming complete independent-source applicability. It adds no native adapter or accepted listing.

Replay verifies the original raw and blended inference plus any fully supported UI refresh using installed exact code; it never executes stored artifact bytes. Public packages exclude private refresh receipts, feature dependencies and artifact bytes. Supported synthetic research estimates can display while remaining PASS at zero stake; Novig FVS keeps binary EV, edge and break-even unavailable. Missing source period/settlement and unsupported NHL/integer-line inference continue to reject. Existing historical packets with no refresh receipt retain their original interpretation and rejection; there is no reconstruction, backfill or availability upgrade.

The [Odds API market definitions](https://the-odds-api.com/sports-odds-data/betting-markets.html), [bookmaker catalog](https://the-odds-api.com/sports-odds-data/bookmaker-apis.html), [terms](https://the-odds-api.com/terms-and-conditions.html), [Novig contracts](https://support.novig.com/en/articles/16083642-contracts) and [FVS explanation](https://support.novig.com/en/articles/16163706-what-is-fair-value-settlement-fvs) support bounded source inspection. Public permissions and templates do not establish owner entitlement, an exact provider-to-listing/product/YES-NO/count bridge, an applicable period/effective edition or a settlement-compatible value reader. Real accepted listings remain empty. The source inquiry, retained packet assessment and separate NFL/NHL development decisions remain private and unsent.

Frozen V1, version 10, prior policy seals/assertions/workflows and owner work remain protected. Evidence integrity is separate from scoped calibration, uncertainty, chronological validation/untouched holdout, scientific acceptance, production-reader acceptance and later activation/exposure authority. This PR authorizes no acquisition, recovery, fitting, receipt/protocol registration, activation or wagering.
