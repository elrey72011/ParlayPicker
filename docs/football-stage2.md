# Football Stage 2 research models

Run the existing `Football Stage 1 data foundation` workflow with its `stage2_audit` dispatch input on the Stage 2 branch; after merge, the dedicated `Football Stage 2 research model audit` workflow is also available. Both paths first perform an authenticated Stage 1 refresh, remote backup, and read-back. Stage 2 refuses to run if that proof is absent, even when the requested slate had a partial provider failure. The workflow uploads eight sanitized JSON reports, plus content-addressed model or calibration artifacts only if a scope passes its training gates. No model is written to the production model registry, and no prediction, activation, stake, parlay leg, or wager is created.

Four scopes are independent: NFL Spread, NFL Total, NCAAF Spread, and NCAAF Total. The only training source is Stage 1.1's deterministic one-game/market manifest. Every selected row is rechecked against immutable source hashes, a verified quote before kickoff, final result availability, exact line settlement, and the small as-of feature contract. Other books and reprices stay in the audit but cannot increase independent `n`. The legacy canonical ledger, repository CSVs, and three owner-attached CSVs are inventoried separately and are never promoted without the Stage 1 chain. The offline CSV inventory records source SHA-256 values in [football-stage2-local-candidate-sources.json](audits/football-stage2-local-candidate-sources.json); those files are not present on GitHub Actions runners.

## Frozen training design

The versioned `football-market-schedule-asof-v1` schema uses only the exact stored line, its American-odds implied chance, scheduled neutral-site flag, and selection orientation. Each field carries an availability timestamp no later than the quote. Historical team statistics, roster/injury reports, rankings, weather, closing prices, and TheOver measures stay excluded until their historical as-of lineage is independently reproducible. `ModelHitRate` is never a per-game probability, and blank TheOver `WinProbability` stays null.

Games are ordered by kickoff, with a shared per-sport assignment across Spread and Total. The intended development, selection validation, calibration candidate, and untouched research holdout proportions are 55/15/15/15 percent. A scope requires at least 200/60/60/60 independent games respectively, two seasons, five observations of each exact target class in development, and result availability before the next partition's quote time. These are prespecified minimum engineering gates for fitting a three-class model, not a claim of statistical power or prospective validation. If any gate fails, the model ID is null and the status is `INSUFFICIENT_TRAINING_EVIDENCE`.

Eligible scopes compare Laplace-smoothed base rate and price-implied benchmarks against a regularized three-class logistic candidate. Brier and log loss must both improve on both baselines. Calibration uses only its separate chronological cohort and requires a nonidentity temperature fit with improved log loss and no material Brier regression; otherwise the calibration ID remains null. The research holdout is read only after selection and calibration. Metrics include multiclass Brier, log loss, calibration error, coverage, hit rate, class balance, push rate, and nonpush AUC when defined. Small-sample metrics are descriptive; no confidence interval or validation pass is claimed.

Any selected model artifact binds exact target classes, feature version, manifest hash, training cutoff and independent count, validation window, algorithm settings, source commit, environment/config/metrics hashes, and creation/availability times. A calibrated research prediction binds the exact game, quote and line, model availability, feature snapshot, timestamp, target vector, and a deterministic descriptive conservative bound. Every such record remains `UNVALIDATED`, production ineligible, and zero stake. Prospective validation requires a later, separate task.
